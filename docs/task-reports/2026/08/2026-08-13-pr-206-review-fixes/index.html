PR #206 Review Fixes

August 13, 2026 Security · Settings Completed

Before

Fingerprint pinning scanned human-readable GPG output, catalog requests followed redirects automatically without guarding alternate private-host literals, and a catalog error replaced the entire model command list.

Problem

Those paths weakened upgrade key pinning, left an SSRF redirect gap, and made ordinary offline or provider-outage settings edits depend on remote catalog availability.

Changes Added

  • Parse only GPG VALIDSIG status records for signing-key fingerprint allowlists.
  • Follow model-catalog redirects manually and reject private or invalid targets, including IPv4-mapped private literals, before the next request.
  • Keep the Use … custom model option visible alongside catalog errors and Retry.

Result

Verified upgrades pin the key that actually produced the signature, syntactically private or invalid redirect targets are rejected before follow-up requests, and users can select a typed model while the catalog is unavailable.
